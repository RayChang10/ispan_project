# FastMCP-FastAgent API 對口修正步驟流程

## 🎯 修正目標

確保前後端 API 串接一致性，統一使用舊版 `/api/job_search/*` API，並修正面試 API 對口問題。

## 🔍 問題分析

### 1. API 不一致問題
- `api.js` 同時定義新舊兩套 API（JobSearchAPI 和 WorkflowAPI）
- 實際使用中混用了不同版本的 API
- 面試 API 使用自定義端點解析，可能連接到錯誤的服務

### 2. RAG 功能確認
- 後端確實使用 RAG（Milvus + OpenAI Embedding）
- 前端透過 `JobMateAPI.JobSearch.*` 調用，間接使用 RAG
- 需要確認所有搜尋功能都正確使用 RAG

## 🛠️ 修正步驟

### 步驟 1：清理 API 定義
**檔案**：`frontend/assets/js/api.js`

**修改內容**：
1. 移除 `WorkflowAPI` 定義（第83-133行）
2. 保留 `JobSearchAPI`（舊版 API）
3. 修正 `window.JobMateAPI` 導出

**修改前**：
```javascript
// 工作流程 API
const WorkflowAPI = {
    // 設定履歷
    async setResume(resumeData) {
        return await apiCall('/workflow/set_resume', {
            method: 'POST',
            body: JSON.stringify({ resume_data: resumeData })
        });
    },
    // ... 其他 Workflow API
};

// 導出 API 模組
window.JobMateAPI = {
    JobSearch: JobSearchAPI,
    Workflow: WorkflowAPI,  // 移除這行
    Interview: InterviewAPI,
    Auth: AuthAPI,
    apiCall,
    resolveApiBase
};
```

**修改後**：
```javascript
// 導出 API 模組
window.JobMateAPI = {
    JobSearch: JobSearchAPI,
    Interview: InterviewAPI,
    Auth: AuthAPI,
    apiCall,
    resolveApiBase
};
```

### 步驟 2：修正面試 API 對口
**檔案**：`frontend/assets/js/interview.js`

**修改內容**：
1. 移除自定義 API 解析邏輯
2. 使用統一的 API 調用方式
3. 確保連接到正確的後端服務

**修改前**：
```javascript
// ---- 與後端面試 API 串接 ----
let INTERVIEW_API = '';
async function resolveInterviewApi() {
    if (INTERVIEW_API) return INTERVIEW_API;
    const candidates = [
        '/api/interview',
        'http://localhost:5000/api/interview',
        'http://localhost:8001/api/interview',
        'http://localhost:8080/api/interview'
    ];
    // ... 複雜的端點解析邏輯
}

async function callInterview(message) {
    const endpoint = await resolveInterviewApi();
    const userId = localStorage.getItem('jobmate_user_id') || 'default_user';
    const res = await fetch(endpoint, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ message, user_id: userId })
    });
    // ... 複雜的響應處理
}
```

**修改後**：
```javascript
// 使用統一的 API 調用
async function callInterview(message) {
    try {
        const userId = localStorage.getItem('jobmate_user_id') || 'default_user';
        const result = await window.JobMateAPI.Interview.sendMessage(message, userId);
        return result.response || result.message || '系統忙碌中，請稍後再試。';
    } catch (error) {
        console.error('面試 API 調用失敗:', error);
        return '呼叫面試服務失敗，請稍後再試。';
    }
}
```

### 步驟 3：確認 RAG 功能使用
**檔案**：`frontend/assets/js/matching.js`

**檢查內容**：
1. 確認所有搜尋都使用 `JobMateAPI.JobSearch.*`
2. 驗證後端 RAG 功能正常運作

**確認點**：
```javascript
// 這些調用都會透過後端使用 RAG
result = await window.JobMateAPI.JobSearch.searchJobsByResume(resumeData, query);
result = await window.JobMateAPI.JobSearch.searchJobs(query, 10);
const fitResult = await window.JobMateAPI.JobSearch.analyzeFit(resumeData, job);
```

### 步驟 4：統一履歷健檢 API
**檔案**：`frontend/assets/js/review.js`

**確認內容**：
1. 確認使用 `JobMateAPI.JobSearch.resumeHealthCheck`
2. 移除任何 Workflow API 的使用

**確認點**：

```javascript
const result = await window.JobMateAPI.JobSearch.resumeHealthCheck(currentData, selectedJob);
```
